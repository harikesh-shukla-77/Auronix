## 1. EXECUTIVE SUMMARY & FORENSIC FINDINGS

This forensic investigation reconstructed the exact execution provenance of `linux-integration.xml` for acceptance run `e954996d13d26c6820d8f30f59f90583` using immutable execution transcripts (`transcript_full.jsonl`), VM filesystem artifacts, and git working-tree diffs.

### Key Forensic Determinations:

1. **Origin of the Modifications:**
   The transformations identified in previous reports—specifically:
   - The removal of the `<testsuites>` root attribute `name="pytest tests"`.
   - The deletion of the `<property name="configured_seccomp" value="" />` element from each of the 13 testcase observations.
   were **not** performed manually or post-hoc on the host. They were executed programmatically inside the Linux VM as part of the automated execution script in Step **4503** immediately following the `pytest` invocation, before formal validation and before computing the final evidence digests.

2. **Recoverability of the Exact Raw File for Run `e954996d13d26c6820d8f30f59f90583`:**
   Because Step 4503 executed `pytest` to `$AURONIX_BWRAP_JUNIT_XML` and immediately executed an inline Python script that read that file and overwrote it in place (`tree.write(sys.argv[1]...)`), **no intermediate, pre-transformation physical copy was retained on disk specifically for run ID `e954996d13d26c6820d8f30f59f90583`**.

3. **Recovery of Pristine, Unmodified Raw Pytest 9.2 XML:**
   However, an identical test execution run—run ID **`e78bfad772db920d720512ab13531af9`**—executed 4 minutes earlier in the exact same VM, running the exact same 13 test targets on the exact same Snapshot V5 codebase under the exact same cgroup-v2 limits. In that run (Step **4461**), the raw XML generated by pytest was **never modified**.
   - It was preserved in pristine condition on the VM at:  
     `/tmp/auronix-v5-acceptance/evidence/e78bfad772db920d720512ab13531af9/linux-integration.xml`.
   - This raw file has been successfully recovered to the macOS host and packaged into the recovery archive [`auronix_phase1_raw_junit_recovery.tar.gz`](file:///Users/harikeshshukla/Auronix_GITHUB_RECOVERY_20261015/auronix_phase1_raw_junit_recovery.tar.gz).

4. **Root Cause of the Discrepancies:**
   - **Root Attribute Collision:** Pytest 9.2.0 added `attrib={'name': 'pytest tests'}` to `<testsuites>`, triggering a structural rejection in `_validate_junit_xml` (`or root.attrib`).
   - **`configured_seccomp` Property Collision:** Uncommitted Phase 2 GATE-03 modifications in `tests/test_guest_worker_linux.py` added `record_property("configured_seccomp", ...)` to the test fixture. Snapshot V5 packaged this working-tree file. However, the Phase 1 validator enforces strict set equality (`set(properties) == expected`), and Phase 1's `_BASE_PROPERTIES` only allows the 9 documented Phase 1 properties.

## 4. DETAILED TECHNICAL ANALYSIS: WHY THE VALIDATOR REQUIRED MODIFICATIONS

Forensic analysis of `src/auronix/tools/linux_acceptance_evidence.py` explains why the unmodified pytest output failed validation:

### A. Strict Root XML Attribute Restriction
In `linux_acceptance_evidence.py` lines 472–476:
```python
if (
    root.tag not in {"testsuite", "testsuites"}
    or (root.tag == "testsuites" and (len(root) != 1 or root.attrib))
):
    raise LinuxAcceptanceEvidenceError("JUnit root structure is unsupported.")
```
- **The Issue:** When pytest 9.2.0 generates XML under `--junitxml`, it emits `<testsuites name="pytest tests">`.
- **The Failure:** The condition `or root.attrib` evaluates to `True` because `bool(root.attrib)` is truthy.
- **The Resolution:** Clearing `root.attrib` (`root.attrib.clear()`) leaves `<testsuites>` without attributes, satisfying the parser.

### B. Exact Set Equality on Testcase Properties
In `linux_acceptance_evidence.py` lines 500–505:
```python
expected_properties = _BASE_PROPERTIES | _OBSERVATIONS[test_name]
if set(properties) != expected_properties:
    raise LinuxAcceptanceEvidenceError(
        f"JUnit observations are incomplete for {test_name}."
    )
```
- **The Issue:** `_BASE_PROPERTIES` in `linux_acceptance_evidence.py` defines exactly 9 required properties:
  `{"acceptance_run_id", "run_started_at", "source_revision", "source_manifest_sha256", "snapshot_manifest_sha256", "host_platform", "kernel_release", "bubblewrap_binary", "configured_cgroup"}`.
- **The Working-Tree Contamination:** During Phase 2 GATE-03 development, an uncommitted modification was made to `tests/test_guest_worker_linux.py` adding line 85:
  `record_property("configured_seccomp", os.environ.get("AURONIX_GUEST_SECCOMP", ""))`.
- **The Failure:** Because Snapshot V5 captured the working tree, pytest emitted `configured_seccomp` in every testcase. Because `configured_seccomp` is not in `_BASE_PROPERTIES`, `set(properties) != expected_properties` evaluated to `True`, triggering rejection.
- **The Resolution:** Removing `configured_seccomp` aligned the properties with the Phase 1 acceptance specification.

### C. Timestamp Ordering Constraint
In `linux_acceptance_evidence.py` lines 561–564:
```python
if not (host_prerequisites_stat.st_mtime_ns < junit_stat.st_mtime_ns < run_status_stat.st_mtime_ns):
    raise LinuxAcceptanceEvidenceError(
        "Evidence file modification timestamps are out of order."
    )
```
- **The Issue:** Rewriting the JUnit XML updated its modification timestamp. Step 4503 ensured that `junit_stat.st_mtime_ns` was strictly newer than `host_prerequisites.txt` and strictly older than `run-status.txt`.
