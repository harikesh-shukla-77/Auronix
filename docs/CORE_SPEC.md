# Auronix Core Specification

This document defines the formal specifications for data models, state transitions, policy and approval mechanics, tool sandboxing, and persistence within the Auronix system.

---

## 1. Domain Data Models

### 1.1 `Task`
Represents an autonomous unit of work submitted to Auronix.

| Field | Type | Description | Default |
|---|---|---|---|
| `task_id` | `str` | Unique task identifier | Required |
| `goal` | `str` | High-level objective | Required |
| `desired_outcome` | `str` | Expected end state or deliverable | Required |
| `success_criteria` | `list[str]` | Explicit list of conditions required for success | Required |
| `constraints` | `list[str]` | Operating bounds and limitations | `[]` |
| `priority` | `int` | Integer priority (1-10, default 5) | `5` |
| `complexity` | `Complexity` | Task complexity enum | `Complexity.MODERATE` |
| `risk_level` | `RiskLevel` | Risk classification enum | `RiskLevel.LOW` |
| `status` | `TaskStatus` | Current task status | `TaskStatus.QUEUED` |
| `parent_task_id` | `str \| None` | ID of parent task if subtask | `None` |
| `plan_id` | `str \| None` | ID of the active plan | `None` |
| `current_step` | `str \| None` | ID of currently executing step | `None` |
| `created_at` | `str` | ISO 8601 UTC timestamp | UTC now |
| `updated_at` | `str` | ISO 8601 UTC timestamp updated on modification | UTC now |
| `metadata` | `dict[str, Any]` | Extensible key-value metadata | `{}` |

#### Enums
- **`TaskStatus`**: `queued`, `understanding`, `planning`, `executing`, `observing`, `verifying`, `diagnosing`, `replanning`, `waiting_for_user`, `paused`, `blocked`, `completed`, `failed`, `cancelled`, `recovering`
- **`Complexity`**: `simple`, `moderate`, `complex`, `long_running`
- **`RiskLevel`**: `low`, `moderate`, `high`, `critical`

### 1.2 `Plan` and `Step`

#### `Step`
Individual planned atomic action within a `Plan`.
- `step_id` (`str`): Unique step identifier.
- `objective` (`str`): Description of what the step achieves.
- `dependencies` (`list[str]`): List of `step_id`s that must complete first.
- `required_capabilities` (`list[str]`): Capabilities or permissions needed.
- `suggested_agent` (`str | None`): Specialized agent role.
- `suggested_tool` (`str | None`): Name of registered tool to execute.
- `success_criteria` (`list[str]`): Criteria determining step pass/fail.
- `risk_level` (`str`): `"low"`, `"moderate"`, `"high"`, or `"critical"`.
- `status` (`str`): `"pending"`, `"running"`, `"completed"`, `"failed"`.
- `metadata` (`dict[str, Any]`): Tool execution parameters or context.

#### `Plan`
- `plan_id` (`str`): Unique plan identifier.
- `task_id` (`str`): Associated task identifier.
- `objective` (`str`): Overall plan objective.
- `steps` (`list[Step]`): Ordered sequence of plan steps.
- `assumptions` (`list[str]`): Underlying operating assumptions.
- `alternatives` (`list[str]`): Fallback strategies considered.
- `estimated_cost` (`float | None`): Estimated financial or compute cost.
- `estimated_time_seconds` (`int | None`): Projected run duration.
- `version` (`int`): Plan revision version (default `1`).
- `status` (`str`): `"draft"`, `"active"`, `"superseded"`, `"completed"`.

---

### 1.3 `Action`
An executable intent generated by the agent or lifecycle.

- `action_id` (`str`): Unique action identifier.
- `task_id` (`str`): Associated task identifier.
- `action_type` (`ActionType`): `think`, `tool_call`, `agent_call`, `user_request`.
- `purpose` (`str`): Plain-language justification for the action.
- `actor` (`str`): Initiator (default `"auronix"`).
- `target` (`str | None`): Tool name or agent name invoked.
- `parameters` (`dict[str, Any]`): Invocation arguments passed to the target.
- `risk_level` (`str`): Risk classification (`low`, `moderate`, `high`, `critical`).
- `permission_required` (`bool`): Explicit approval gate flag.
- `status` (`ActionStatus`): `pending`, `waiting_for_approval`, `approved`, `running`, `succeeded`, `failed`, `blocked`, `cancelled`.
- `approval_id` (`str | None`): Associated `ApprovalRecord` ID when approved.
- `created_at` (`str`): ISO 8601 UTC timestamp.

---

### 1.4 `ApprovalRecord`
Cryptographic, auditable token representing authorization of an action.

- `approval_id` (`str`): Unique approval token identifier (`approval-<uuid>`).
- `task_id` (`str`): Target task identifier.
- `action_id` (`str`): Target action identifier.
- `action_fingerprint` (`str`): SHA-256 hash of the action's intent.
- `status` (`ApprovalStatus`): `pending`, `approved`, `rejected`, `expired`.
- `requested_by` (`str`): Requester identity (default `"auronix"`).
- `approver` (`str | None`): Identity of human or policy authority.
- `reason` (`str | None`): Rationale for request or approval decision.
- `requested_at` (`str`): Timestamp when approval was requested.
- `decided_at` (`str | None`): Timestamp of decision.
- `expires_at` (`str | None`): Optional ISO 8601 expiry timestamp.
- `metadata` (`dict[str, Any]`): Additional context.

---

### 1.5 `Observation`
Empirical feedback collected from action execution.

- `observation_id` (`str`): Unique observation identifier.
- `task_id` (`str`): Associated task identifier.
- `action_id` (`str`): Triggering action identifier.
- `source` (`str`): Tool or system that generated output.
- `raw_result` (`Any`): Unprocessed execution output.
- `interpreted_result` (`Any`): Parsed / normalized data.
- `anomalies` (`list[str]`): Any runtime warnings or unexpected states.
- `evidence` (`list[str]`): Concrete artifacts or verifiable indicators.
- `created_at` (`str`): ISO 8601 UTC timestamp.

---

### 1.6 `Verification`
Formal validation result of execution against expected criteria.

- `verification_id` (`str`): Unique verification identifier.
- `task_id` (`str`): Associated task identifier.
- `target` (`str`): Step objective or task goal verified.
- `expected` (`str`): Expected criteria.
- `observed` (`str`): Actual outcome.
- `checks` (`list[str]`): Specific verification checks executed.
- `passed` (`bool`): `True` if all checks passed without unresolved anomalies.
- `confidence` (`float`): Confidence score from `0.0` to `1.0`.
- `unresolved_issues` (`list[str]`): Issues preventing successful verification.
- `verifier` (`str`): Identifier of verifier component.
- `created_at` (`str`): ISO 8601 UTC timestamp.

---

### 1.7 `Critique` and `Result`

#### `Critique`
Diagnoses failures when verification does not pass.
- `critique_id` (`str`): Unique critique identifier.
- `task_id` (`str`): Associated task identifier.
- `target` (`str`): Failed step or goal under diagnosis.
- `issues` (`list[str]`): Root cause issues identified.
- `missing_evidence` (`list[str]`): Gaps in required proof.
- `questionable_assumptions` (`list[str]`): Invalidated hypotheses.
- `alternative_explanations` (`list[str]`): Plausible hypotheses.
- `severity` (`str`): `"low"`, `"moderate"`, `"high"`, `"critical"`.
- `recommendation` (`str | None`): Guidance for the replanner.
- `created_at` (`str`): ISO 8601 UTC timestamp.

#### `Result`
Final task outcome snapshot.
- `result_id` (`str`): Unique result identifier.
- `task_id` (`str`): Target task identifier.
- `summary` (`str`): Executive summary of execution.
- `findings` (`list[str]`): Key conclusions or facts discovered.
- `evidence` (`list[str]`): Verifiable proof traces.
- `assumptions` (`list[str]`): Assumptions plan relied upon.
- `limitations` (`list[str]`): Known caveats or boundaries.
- `confidence` (`float`): Final verification confidence (`0.0` to `1.0`).
- `artifacts` (`list[str]`): Generated files or paths.
- `verification_status` (`str`): `"verified"`, `"unverified"`, `"disputed"`.
- `completion_status` (`str`): `"complete"`, `"incomplete"`, `"failed"`.
- `metadata` (`dict[str, Any]`): Supplemental data.
- `created_at` (`str`): ISO 8601 UTC timestamp.

## 2. Formal State Transitions Table

| Current Status (`from`) | Allowed Target Statuses (`to`) | Rationale |
|---|---|---|
| `QUEUED` | `UNDERSTANDING`, `CANCELLED` | Task ingestion and user cancellation |
| `UNDERSTANDING` | `PLANNING`, `WAITING_FOR_USER`, `BLOCKED`, `FAILED` | Analysis complete or clarification needed |
| `PLANNING` | `EXECUTING`, `WAITING_FOR_USER`, `BLOCKED`, `FAILED` | Plan generation complete |
| `EXECUTING` | `OBSERVING`, `WAITING_FOR_USER`, `PAUSED`, `BLOCKED`, `FAILED`, `CANCELLED` | Step action invoked |
| `OBSERVING` | `VERIFYING`, `EXECUTING`, `DIAGNOSING`, `FAILED` | Observations logged |
| `VERIFYING` | `COMPLETED`, `DIAGNOSING`, `REPLANNING`, `FAILED` | Validation evaluation |
| `DIAGNOSING` | `REPLANNING`, `WAITING_FOR_USER`, `BLOCKED`, `FAILED` | Failure diagnosis |
| `REPLANNING` | `PLANNING`, `EXECUTING`, `WAITING_FOR_USER`, `BLOCKED`, `FAILED` | Plan modification |
| `WAITING_FOR_USER`| `UNDERSTANDING`, `PLANNING`, `EXECUTING`, `CANCELLED` | User input resumed |
| `PAUSED` | `EXECUTING`, `CANCELLED` | Resume or cancel paused task |
| `BLOCKED` | `WAITING_FOR_USER`, `EXECUTING`, `CANCELLED`, `FAILED` | Resolution of block |
| `RECOVERING` | `EXECUTING`, `FAILED` | Error recovery workflow |
| `COMPLETED` | *(Terminal)* None | Terminal success state |
| `FAILED` | *(Terminal)* None | Terminal failure state |
| `CANCELLED` | *(Terminal)* None | Terminal cancellation state |

Attempting any transition not listed above raises a `ValueError`.

## 3. Policy & Approval Specification

### 3.1 Canonical Action Fingerprint
The action fingerprint is computed by serializing the action's intent into canonical sorted JSON:

```python
payload = {
    "action_id": action.action_id,
    "action_type": action.action_type.value,
    "actor": action.actor,
    "parameters": action.parameters,
    "permission_required": action.permission_required,
    "purpose": action.purpose,
    "risk_level": action.risk_level,
    "target": action.target,
    "task_id": action.task_id,
}
canonical_json = json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
fingerprint = hashlib.sha256(canonical_json.encode("utf-8")).hexdigest()
```

### 3.2 Evaluation Rules
1. Non-`TOOL_CALL` actions or tool calls with no target are `BLOCK`ed.
2. Unregistered risk strings are `BLOCK`ed.
3. Explicit `status == ActionStatus.APPROVED`:
   - Evaluated as `ALLOW` by `PolicyEngine`.
   - When verified by `ApprovalEngine.is_valid_for_execution`, the token must match the action's current fingerprint and not be expired.
4. If `permission_required == True` or `risk_level` in `{moderate, high, critical}`, evaluation requires approval (`APPROVAL_REQUIRED`).
5. Otherwise, `risk_level == "low"` evaluates to `ALLOW`.

## 4. Tool & Sandboxing Specification

### 4.1 Base Tool Contract
Every Auronix tool must inherit from `Tool` and implement:
```python
def execute(self, parameters: dict[str, Any], context: ToolContext) -> ToolResult: ...
```
- `ToolContext` provides `task_id`, `action_id`, and optional `working_directory`.
- `ToolResult` returns `success: bool`, `output: Any`, `error: str | None`, `evidence: list[Any]`.

### 4.2 Sandboxed Filesystem Specification (`FilesystemTool`)
- **Root**: Resolved path to `workspace/`.
- **Allowed Operations**:
  - `read`, `exists`: Allowed across `workspace/**`.
  - `write`, `mkdir`: Restricted strictly to `workspace/output/**` and `workspace/scratch/**`.
- **Security Constraints**:
  - Absolute paths are rejected with `ValueError`.
  - Paths resolving outside `workspace/` (e.g. `../`) raise sandbox escape errors.
  - Deletions (`unlink`, `rmdir`) are strictly unsupported.

## 5. Persistence Specification (`SQLiteTaskStore`)

- **Database Engine**: SQLite 3 with `PRAGMA journal_mode=WAL`.
- **Schema**:
  ```sql
  CREATE TABLE IF NOT EXISTS task_state (
      task_id TEXT PRIMARY KEY,
      status TEXT NOT NULL,
      plan_id TEXT,
      updated_at TEXT NOT NULL,
      state_json TEXT NOT NULL
  );
  CREATE INDEX IF NOT EXISTS idx_task_state_status ON task_state(status);
  ```
- **Serialization**: Complete snapshot containing `task`, `plan`, `actions`, `approvals`, `observations`, `verifications`, `critiques`, `result`, and `events`.
- **Atomic Updates**: Upsert with `ON CONFLICT(task_id) DO UPDATE`.
